只換成新的自動 ID 與圖片路徑；另外「古都Laz」保留為 1 筆新草稿。

內容
- data/works.js：合併好的作品資料（25 筆，每筆只留必要的 8 欄）
- data/import-history.json：匯入歷史；存放檔名/雜湊/差分/曾公開狀態，不放入作品資料
- watch-gallery.js：新版監看器，新匯入作品優先用角色＋繪師＋完稿日對照既有資料
- 啟動自動監看.cmd：啟動監看
- 合併對照表.csv：舊 ID → 新 ID，以及差分對應，方便核對

安裝順序（重要）
1. 請先關掉所有舊版「啟動自動監看」視窗，避免兩支程式同時修改資料。
2. 先備份整份 Gallery，尤其是 data/works.js、data/artists.js、images/。
3. 將 ZIP 內的檔案複製到 Gallery 根目錄，維持 data/ 子目錄結構，覆蓋舊版 watch-gallery.js 和 works.js。
4. 確保電腦上 images/ 仍有本次匯入生成的 art-*.jpg，以及 images/thumbs/ 裡的同名縮圖。
5. 雙擊「啟動自動監看.cmd」。監看器會驗證已公開作品的圖片，再重新產生作品頁。
6. 後續把原圖放入「匯入原圖」資料夾，符合檔名規則就自動轉 1920×1080 + 640×360。
7. 對新作品在 data/works.js 補 title 並存檔，就會自動公開（僅作用於匯入記錄內尚未公開的草稿）。
8. 確認網站正常後再執行 git add .、git commit、git push。

標準檔名：角色 -繪師 リクエストYYMMDD.jpg/png/webp/tiff
差分檔名：角色 -繪師 リクエストYYMMDD-1.jpg、...-2.jpg
YYMMDD 一律代表完稿日。

- 本版暫依舊資料排列順序對應：-1→「結婚しました」；-2→「お幸せに」。
- 請打開這兩張圖片親自確認！若反過來，請先停止監看器，再調換兩筆作品的 title（如手機位置不同亦需調整）。不要隨意改動自動 ID 和圖片路徑。

資料欄位
works.js 只保留：id、title、date、character、artist、published、image、mobilePosition。
importSource、importHash、autoPublishWhenTitled：不需要存在 works.js。
安全去重仍然需要匯入歷史，因此搬到 data/import-history.json。
當新作品 title 補上時，監看器由 history 的 publishedOnce 決定是否自動發布。
對已公開作品，日後手動設 published:false，不會被監看器重新公開。

安全規則
- 只有圖片與縮圖存在、資料正確、作品頁產生成功時才刪除「匯入原圖」中的副本。
- 如果檔名不符、內容衝突、作品匹配不唯一或網站圖片缺失，原檔保留。
- 本工具不刪除舊網站圖片，也不執行 git push。舊版圖檔若不再使用，需自行核對後清理。
- 原始檔不必長期放在匯入資料夾，但請務必先在雲端保存真正原圖。
- 變更作品 ID 將變更獨立作品網址；先前分享的舊網址可能失效。
